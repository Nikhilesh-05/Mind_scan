# Product Backlog Refinement
## Overview of the Product Backlog
The Product Backlog for "MindScan: Multimodal Depression Detection System" was constructed using MS Planner to ensure clear tracking of features, continuous prioritization, and transparent progress monitoring.

## User Stories & Acceptance Criteria

**User Story 1: User Registration & Authentication**
*As a new user, I want to securely register and log into the system so that my personal data and analysis history remain private.*
- **Acceptance Criteria:**
  - User can sign up using email and password.
  - Passwords are encrypted using bcrypt before being stored in the database.
  - Upon successful login, the system generates and returns a JWT token for secure subsequent requests.
  - System denies access to dashboard routes without a valid JWT token.

**User Story 2: Real-time Audio Sentiment Analysis**
*As an end-user, I want the system to record and analyze my voice in real-time so that it can extract prosodic features and sentiment.*
- **Acceptance Criteria:**
  - The UI provides clear "Start Recording" and "Stop Recording" buttons.
  - Recorded audio is visually mapped using an audio waveform display.
  - Audio data is transmitted to the backend for processing.
  - The system returns detected emotion (e.g., Happy, Neutral, Sad), confidence score, and prosodic metrics (Pitch, Energy).

**User Story 3: Live Video Emotion Detection**
*As an end-user, I want the system to analyze my facial expressions via my webcam so that it can detect my emotions over a 30-second timeframe.*
- **Acceptance Criteria:**
  - A 30-second countdown timer initiates upon camera authorization.
  - The UI renders a targeting box to help users focus their face in the center.
  - The system processes facial frames and smooths transient emotions to prevent flickering.
  - Emotional history is aggregated, and the dominant emotion is summarized at the end of the recording.

**User Story 4: Sarvam AI Multimodal Fusion Report**
*As a user seeking mental health insights, I want the system to combine my chat, audio, and video data into a single unified report.*
- **Acceptance Criteria:**
  - The system calculates text risk (based on sentiment/PHQ-9), audio risk, and video risk.
  - A comprehensive "Fusion Score" is mathematically generated based on modality weights.
  - The user receives a clear, actionable risk assessment (Low, Moderate, High).
  - The system provides a downloadable PDF containing a summary of risk factors and personalized recommendations.

**User Story 5: Interactive Chatbot for Cognitive Assessment**
*As an end-user, I want to converse with an AI chatbot so that my linguistic patterns and text sentiment can be analyzed for depressive markers.*
- **Acceptance Criteria:**
  - The chat interface supports natural, multi-turn dialogue.
  - Chat inputs are analyzed in real-time to extract positive, negative, and neutral sentiment probabilities.
  - The system visually displays the detected sentiment score alongside user messages.

**User Story 6: Clinical PHQ-9 Signal Extraction**
*As a clinician reviewing the data, I want the text analysis engine to map user responses to standard PHQ-9 depression indicators (e.g., fatigue, anhedonia).*
- **Acceptance Criteria:**
  - The NLP backend identifies keyword concepts mapped directly to the 9 PHQ-9 clinical criteria.
  - A summary of active indicators is stored in the `chat_results` database table and relayed to the Fusion Engine.

**User Story 7: Real-time Dashboard Analytics**
*As a user, I want a central dashboard where I can view my past session records and track my mental wellness history over time.*
- **Acceptance Criteria:**
  - The dashboard automatically fetches all completed `AnalysisReport` entities linked to the user's account.
  - Users can view a list of past sessions with timestamps, risk levels, and Fusion Scores.
  - Users can easily navigate to detailed views of past reports.

**User Story 8: Responsive & Accessible User Interface**
*As a mobile user, I want the application to function seamlessly on my smartphone so that I can perform a mental health check from anywhere.*
- **Acceptance Criteria:**
  - The UI (including sidebar, dashboard, and media recorders) is fully responsive utilizing Tailwind CSS grid/flex layouts.
  - Video and audio capture elements adapt cleanly to smaller screen dimensions without breaking layout constraints.

**User Story 9: Data Privacy & Ephemeral Processing**
*As a privacy-conscious user, I want assurance that my sensitive audio and video recordings are not permanently stored on the server.*
- **Acceptance Criteria:**
  - Media streams (audio and video) are processed in real-time or via volatile memory.
  - The database only saves the mathematically extracted features (e.g., pitch arrays, emotion confidence labels) rather than the raw MP4/WAV payloads.

**User Story 10: PDF Report Generation & Export**
*As a user who wants to share my results with a therapist, I want the ability to download my detailed Fusion Report as a structured PDF document.*
- **Acceptance Criteria:**
  - The backend provides a secure `/report/download/{id}` API endpoint.
  - Reports are generated dynamically using `fpdf2` and returned as binary attachments.
  - The exported PDF features a professional layout including the user's name, timestamp, risk projections, and disclaimers.

# Sprint Backlog Refinement
## Sprint Goal
**Sprint 1:** Build the core architecture, set up containerization, and implement secure user authentication to establish the foundation of the platform.

### User Stories Committed to Sprint 1
1. User Story 1 (User Registration & Authentication)
2. Database Schema and Project Scaffolding

### List of Tasks (Sprint 1)
- **Task 1.1:** Initialize the Vite + React frontend structure and setup Tailwind CSS.
- **Task 1.2:** Initialize the FastAPI backend and configure Alembic for database migrations.
- **Task 1.3:** Create Docker Compose configuration for PostgreSQL, Redis, Backend, and Frontend containers.
- **Task 1.4:** Define SQLAlchemy ORM models (`User`, `Session`, `ChatResult`, `VideoResult`, `AudioResult`).
- **Task 1.5:** Implement bcrypt password hashing utility.
- **Task 1.6:** Develop the `/auth/register` and `/auth/login` API endpoints using JWT authentication.
- **Task 1.7:** Build the React login and registration screens with Framer Motion animations.
- **Task 1.8:** Create the protected route wrapper logic in the frontend using Zustand global state.
